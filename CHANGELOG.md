## 0.1.0

Initial version.

### Features

- **dashboard:** summarise releases by status, with every status shown including zeros, a
  proportional status bar, click-to-filter chips, and a needs-attention count covering
  blocked, failed and rolled-back releases.
- **inspector:** search components by name, type, path or author with AND-combined tokens;
  facet by type and operation with counts computed against the other active filters; filter
  by release or to components carrying warnings; inspect one component's fields, warnings,
  dependencies and dependents, with dependents clickable so impact is walkable.
- **approvals:** queue pending approvals into waiting-on-you, waiting-on-others and recently
  decided; approve, reject or withdraw with a comment; see the resulting release status
  change reported in place.
- **data:** local-first persistence in `chrome.storage.local` behind a `DataSource` port,
  JSON export, and import of either a previous export or an `sf project deploy report
  --json` payload.
- **demo data:** a five-release, 57-component sample dataset seeded on first run and clearly
  labelled as such.

### Deliberate constraints

- Manifest V3, side panel, `storage` and `sidePanel` permissions only — no host permissions,
  no content scripts, no network access.
- No runtime dependencies; `tsc` output is loaded by Chrome as native ES modules.
- 343 tests covering every exported function, with `jsdom` as the only test-time dependency.
- Approvals are a local workflow aid, not an authenticated or auditable control. See the
  limitations section of the README.
